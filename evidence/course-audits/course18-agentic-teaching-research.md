# 第 18 门课《智能体赋能 K-12 和大学教学》研究简报

> 研究快照：2026-08-26（Asia/Taipei）
> 主要证据：官方/作者 GitHub 仓库与 X 原帖；以官方规范、项目文档、论文与治理指南交叉验证。
> 用途：供 `aicourse.top` 的课程策划、脚本、实验、评测与发布审校使用。
> 可追溯性：文内 `[S01]`—`[S16]` 对应同名 provenance 文件中的固定提交、原始链接和主张台账。

## 一、先给结论

这门课不应教“让一个 AI 自动当老师”，而应教教师、教学设计者和教育技术开发者如何建造一种**证据可追溯、权限有边界、过程可观察、学习可验证、最终责任仍由人承担**的教育智能体系统。

世界级的课程主线不是框架堆叠，而是以下闭环：

`教学目标 → 权威内容 → 智能体与工具 → 教师审批 → 学习者活动 → 无 AI 迁移测验 → 安全/公平复盘 → 小步发布`

三条最重要、且证据强度不同的结论如下。

### 已有直接证据支持的事实

1. 智能体框架已经能提供工具调用、交接、并行/顺序工作流、人工审批、追踪和测试等工程原语，但这些原语本身不等于教学有效。[S01][S02][S05]
2. 在一项覆盖约 50 个班、接近 1,000 名高中数学学生且以班级为随机化单位的实验中，未加教学护栏的通用 GPT 在练习时提高了任务表现，但移除 AI 后的考试表现比对照组低 17%；采用教师输入与提示护栏的 GPT Tutor 大幅缓解了这一负效应，却没有显示独立考试上的正向增益。[S09]
3. Tutor CoPilot 的 K-12 现场实验以导师为随机化单位。ITT 结果显示：获得系统访问权限的导师所教学生，无条件 exit-ticket 通过率由 62% 升至 66%（+4 个百分点）；低评分导师层由 56% 升至 65%（+9 个百分点）。这不是“实际使用某条建议”这一机制的独立因果估计，也不能外推为所有学科、年龄或“AI 替代教师”的证据。[S07]
4. 一项哈佛本科物理课程的交叉随机实验（符合纳入条件的学生 `N=194`）发现，精心设计的定制 AI 导师在相同内容上取得更高的短期学习增益。AI 平台记录的中位任务时间为 49 分钟，课堂学习时间则按研究设计假定为 60 分钟；学生自报投入与动机更高，但享受程度与成长型思维无显著差异。研究对象、课时、学科和系统都很具体，不能直接推广为“AI 普遍优于课堂”。[S10]
5. 一项 2026 年高等教育预印本实验显示，在教师助理完成评分后再提供可编辑的 AI 反馈草稿，反馈提供率提高 10.81 个百分点；把未提供反馈记为 0 后，反馈长度结果增加 39.79 个字符。仅在有相应观测值的子样本中，单位字符耗时和学生有用性评分未见显著组间差异；这两个条件性结果只能作描述性解读，不能支持因果、全体学生体验、自动评分或学习成效结论。[S11]
6. 计算机/浏览器操作可执行点击、输入、上传和提交等真实动作。官方演示明确提示互联网环境、提示注入、敏感凭据与现实后果风险，并建议隔离环境、最小权限、域名白名单及人工确认。[S03][S04]
7. OpenAI Agents SDK 的追踪默认启用，且 `trace_include_sensitive_data` 默认值为 `True`；生成与函数调用的输入输出可能进入追踪。因此，教育场景不能把“可观察”误写为“默认隐私安全”。[S01]
8. UNESCO 与 UNICEF 都把隐私、年龄适切、人类监督、儿童权利、公平、透明、问责和持续评估放在核心位置；它们是治理框架，不是任何地区的直接法律替代品。[S15][S16]

### 基于多源证据的推断

1. **教师/导师副驾驶优先于自主教师**：Tutor CoPilot 与高教反馈实验都把 AI 放在可编辑中间产物的位置；高中数学实验又显示无护栏帮助可能造成“做得更好、学得更差”。因此，中高风险教学任务应先采用人类在环的副驾驶模式。[S07][S09][S11]
2. **迁移测验必须成为验收标准**：使用智能体时的完成率、正确率或满意度无法证明学习；至少要加入移除 AI 后的独立任务、延迟测验或新情境应用。[S09][S10]
3. **MCP 是能力连接协议，不是教学法，也不是完整编排器**：其规范把复杂编排、授权、上下文聚合与安全边界交给 host；课程必须另行定义教学脚本、数据治理、审批与评价。[S02]
4. **多智能体只有在任务可分、接口清楚、可独立验证时才值得使用**：官方项目展示了协调器、并行专家和汇总器，但没有证明“更多智能体让学习更好”。课程应从单智能体基线开始，再用质量、延迟、成本与故障率决定是否升级。[S05][S08][S12][S14]
5. **面向未成年人的“陪伴感”不是普通 UI 特性**：关系化、拟人化和持续记忆会改变儿童风险面。教学智能体应清楚声明其 AI 身份，避免情感依赖设计，并把危机、健康和心理议题交给合格成年人和既有支持流程。[S16]

### 本课程的设计建议

- 默认采用“建议/草拟”，其次才是“经审批执行”；K-12 学生直接交互默认低自主度。
- 每个学习者智能体使用“诊断 → 提示阶梯 → 学生尝试 → 针对误概念反馈 → 反思 → 无 AI 迁移测验”，禁止第一步直接给完整答案。
- 先连接经过批准的只读课程资源，再考虑浏览器和写操作；提交、发布、发送、删除、改分、联系家长等动作必须阻断并交给明确责任人。
- 高风险决定——最终成绩与高风险评估、录取/学校申请、安置、健康/危机与救济——不交给自主智能体。
- 追踪数据默认最小化、去标识化和限期保留；生产环境不得照搬 SDK 的敏感数据默认值。
- 以真实课堂案例建立评测集，并同时测量：内容正确、来源忠实、教学策略、提示泄漏、安全、公平、可访问性、成本、延迟、人工接管率和无 AI 迁移表现。

## 二、证据语言与强度规则

课程文案、讲义和网站应统一使用以下三种标签：

- **事实**：来源明确陈述、规范明确要求、代码明确实现，或实证研究直接报告的结果。
- **推断**：多项事实共同支持的解释，但原始来源没有直接宣称。
- **建议**：课程团队基于风险、教学法和工程可行性作出的设计选择。

证据强度采用四级。等级记录出版/来源状态；“随机化、预注册、随机化单位、样本与结果变量”等设计特征另行记录，不能用设计标签把未同行评审材料提升为 A：

| 级别 | 含义 | 可支持什么 | 不能支持什么 |
|---|---|---|---|
| A | 官方规范/治理文件，或同行评审的现场随机实验 | 规范内容、治理原则、特定研究条件下的因果结果 | 自动推广到所有学校、学科、年龄或模型 |
| B | 工作论文/预印本现场实验，或附代码但尚未同行评审的直接研究 | 特定实现的初步因果/机制证据；预注册和随机化等设计特征另列 | 稳定的跨场景效果、长期效果 |
| C | 官方或维护者 GitHub、技术文档、可运行示例 | 系统能力、架构、接口、已知风险、可复现实验起点 | 教学效果、安全效果、规模化成效 |
| D | 官方/作者 X 原帖 | 发布日期、发布者的产品/架构主张、生态变化信号 | 学习成效、可靠性、普适性 |

硬性边界：

- GitHub stars、forks、下载量只说明可见度或采用信号，**不作为学习效果证据**。
- 开源代码提高可检查性，**不等于系统安全、合规或教学有效**。
- X 帖子的观点和发布宣言，**不作为效果证据**。
- 一次成功轨迹是调试样本，**不等于通过评测**。
- “学生在 AI 帮助下完成任务”与“学生已经学会且能独立迁移”是不同结果。[S09]

## 四、课程定位与学习成果

### 目标学习者

- K-12 教师、课程主任、学校技术/数据负责人；
- 大学教师、助教、教学设计者、教与学中心人员；
- 教育产品经理、工程师、研究者；
- 希望把通用 agent 技术转译为负责任教学实践的进阶学习者。

### 建议先修

- 能阅读基本 Python/TypeScript 示例；
- 理解 prompt、API、JSON 和基本数据隐私概念；
- 至少有一个真实课程、单元或教学支持流程可作为贯穿案例。

### 完课后应能做到

1. 准确区分聊天机器人、copilot、工作流和自主智能体，并绘制 agent loop。
2. 编写一份“教育智能体契约”，明确目标、来源、权限、教师责任、停止条件与成功指标。
3. 使用工具调用和只读 MCP 连接经过批准的课程资源，同时解释 MCP 不负责哪些事。
4. 为浏览器/计算机使用设置沙箱、专用账号、域白名单、读写隔离和审批点。
5. 构建 K-12 提示阶梯导师与大学教师反馈副驾驶，而不越过高风险决定边界。
6. 用单智能体基线比较协调器、并行专家和汇总器等多智能体模式。
7. 设计轨迹评测与结果评测，尤其是无 AI 迁移、延迟保持、公平和人工接管。
8. 制定未成年人隐私、儿童权利、事故响应和分阶段试点方案。

## 五、12 模块课程蓝图

建议按 4 个阶段、12 个模块组织。每个模块由“短讲解 → 源码/原帖阅读 → 失败案例 → 实作 → 证据卡 → 反思”构成。

### 阶段 A：从会聊天到可控行动

| 模块 | 核心问题 | 关键内容与实验 | 产出 | 主要证据 |
|---|---|---|---|---|
| M1 教育智能体是什么 | 什么时候需要 agent，而不是一次对话？ | `目标→计划→工具→观察→修正→停止`；chatbot/copilot/workflow/agent；自主度阶梯；任务表现与学习的区别 | 一个教学任务的 agent loop 与“不用 agent”基线 | S01, S09 |
| M2 教育智能体契约 | 谁负责、可做什么、如何停？ | 教学目标、年龄、来源、工具、数据、审批、禁止输出、停止/升级、评测 | 一页可审计契约 | S01, S15, S16 |

## 七、自主度与风险分级

### 四级自主度

| 等级 | 系统行为 | 教育场景默认 |
|---|---|---|
| L0 建议 | 只给候选与理由，不操作外部系统 | K-12 默认；高风险任务唯一允许级别之一 |
| L1 草拟 | 生成可编辑教案、反馈、问题或摘要 | 教师/TA 审批后使用 |
| L2 经审批执行 | 准备动作，责任人核对具体参数后批准 | 仅批准平台、专用账号和可撤销动作 |
| L3 有界自动执行 | 在沙箱、白名单、限额和回滚内执行低风险重复任务 | 只用于低风险后台任务，不用于学生权益决定 |

### 绿、黄、红任务

- **绿色**：公共资源搜索、格式转换、无个人数据的题目变体草稿、可访问性初稿、教师头脑风暴。可在有日志的 L1/L3 中执行。
- **黄色**：个性化反馈、成绩邻近建议、课程适配、家长摘要草稿、学习预警。必须去标识化、L0/L1、教师审查并允许申诉。
- **红色**：最终成绩与高风险评估、录取/学校申请、安置、健康/危机与救济决定、联系家长、代表学生提交、公开发布、删除记录。不得自主化；如机构确有合法流程，也必须使用经批准系统、明确责任人、逐次审批和本地法律审查。

## 八、K-12 工作流模板

### 1. 标准对齐的 45 分钟备课副驾驶

1. 教师选择课程标准、年级、已学内容与时间。
2. agent 从批准的只读资源检索先备知识、学习顺序、常见误概念与可用素材。[S06]
3. 生成目标、引入、示范、引导练习、独立练习、退出条和差异化建议。
4. 事实核验器逐项回链；可访问性检查器检查语言、对比、替代文本和认知负荷。
5. 教师删改、署名并签发；系统不得直接发布到 LMS。
6. 课后只收集必要结果，更新误概念清单，不把原始对话无限期保留。

### 2. 提示阶梯导师

推荐会话状态机：

`说明目标 → 让学生解释已知 → 首次尝试 → 识别误概念 → 提示 1（方向）→ 提示 2（子步骤）→ 提示 3（相似例）→ 学生重做 → 解释为什么 → 无 AI 新题`

硬性护栏：

- 对原作业/测验题不先给完整答案；
- 每一层提示后等待学生产生可观察尝试；
- 不以“连续对话时的正确率”作为最终学习指标；
- 把反复卡住、情绪危机、疑似伤害或不适龄内容升级给教师/既有支持人员；
- 学生和照护者知道正在与 AI 交互；不得把系统描述为朋友、治疗师或可信赖的知心人，也不得暗示排他性、依赖或情感优先地位。[S09][S16]

### 3. 教师在环的辅导副驾驶

Tutor CoPilot 提供了可借鉴的架构：AI 面向导师，而非直接替代导师；提供多个教学策略，允许选择、编辑或重新生成，并对外发数据去标识和最小化。[S07]

课程实验应复刻的是**人类控制结构**，不是照搬效果数字。验收包括：

- 建议是否适合年级；
- 是否优先使用追问、引导和解释，而非给答案/泛泛表扬；
- 导师采纳、编辑、拒绝的比例及原因；
- 不同经验导师和不同学习者群体的差异；
- 学生无 AI 的新题表现。

### 4. 不建议的 K-12 自动化

- 自动生成并发送家长沟通；
- 根据对话自动作高风险评估、安置、学校申请、健康/危机或救济决定；
- 上传可识别 IEP、健康、辅导或行为记录到未批准服务；
- 让 AI 模拟朋友、治疗师或可信赖的知心人，或暗示排他性、依赖或情感优先地位；
- 用一次对话给学生贴“能力低”“动机不足”等长期标签。

## 九、大学教学工作流模板

### 1. 证据化阅读包

输入课程大纲、许可范围内的阅读材料和本周目标。agent 输出：每篇来源的中心主张、方法/证据、争议、与课程目标的关系、可追问问题及精确出处。引用核验器必须打开原文核对；找不到就标“未核实”，不得补造 DOI、页码或引文。

### 2. 苏格拉底研讨副驾驶

agent 只负责提出层层递进的问题、记录观点分歧、邀请证据与反例；不替学生写讨论帖。完成后要求学生在无 AI 情况下写 200 字论证，并标记哪些想法来自资料、同伴和 AI。

### 3. 实验/编程排错导师

状态机为“复述现象 → 索取最小复现 → 要求预测 → 建议一个诊断 → 学生观察 → 更新假设”。只有在学生展示尝试后才给更具体的提示；最终要求学生解释根因和验证方式，而不是仅复制修复代码。

### 4. 人先判断、AI 后起草的反馈

1. TA/教师先根据 rubric 完成成绩或水平判断。
2. 系统在该判断之后生成一份具体、可操作、证据对齐的反馈草稿。
3. TA 可使用、编辑或忽略，并看到原作业片段和 rubric 依据。
4. 记录编辑差异、采纳率、耗时、学生有用性评价与后续修订质量。
5. 不把反馈更长或提供率更高等同为学生学得更多。[S11]

## 十、MCP、浏览器与工具的课程底线

### MCP 的正确教学表述

**事实**：MCP 采用 host-client-server 架构；每个 client 与一个 server 通信；server 暴露 resources、tools 和 prompts；host 负责权限、授权、安全策略、用户同意、复杂编排和跨 client 的上下文聚合。[S02]

**推断**：学校应把每个课程/数据 server 当作独立信任边界，按最小必要上下文提供数据。

**建议**：第一个教育 MCP 实验只提供只读、无学生个人数据的课程检索工具；所有写工具另建 server、另设身份、另走审批。

必须强调：

- 连接 server 是信任决定；本地 STDIO server 不是沙箱，并可能与 client 拥有等效环境权限。[S02]
- LLM 可能调用用户没有逐字要求的工具；这属于应用控制要解决的行为风险。[S02]
- 规范版本、传输和授权会变；课程代码要记录协议版本和固定提交。
- curriculum grounding 降低“无来源生成”的风险，但不自动保证年级适切、事实正确、许可合规或教学有效。[S06]

### 浏览器/计算机使用的动作边界

| 动作 | 风险级别 | 默认控制 |
|---|---|---|
| 打开公开页、读取、截图、抽取 | 低到中 | 域白名单、记录 URL/时间、抗提示注入规则 |
| 登录、读取机构内部页 | 中到高 | 专用最小权限账号、短会话、禁止保存敏感凭据 |
| 输入学生内容、上传文件 | 高 | 先分类/去标识；仅批准系统；逐次人工确认 |
| 点击提交、发送、发布、接受条款 | 高 | 展示目标、接收者和完整载荷；责任人显式批准 |
| 删除、改成绩、改变权限、支付 | 极高 | 课程实验禁用；真实系统仅走机构既有强控制流程 |

每次有副作用的动作都应执行“预览 → 参数核对 → 人工批准 → 执行 → 页面/系统状态再验证 → 可撤销记录”。[S03][S04]

## 十一、多智能体：先证明必要，再增加角色

### 适合拆分的教学任务

- 课程标准/来源检索；
- 教学策略与认知负荷审查；
- 年龄与语言适切性审查；
- 可访问性审查；
- 安全、隐私与权限审查；
- 引用/答案核验；
- 最终汇总与冲突呈现。

### 不适合拆分的情况

- 一个短、线性、低风险任务；
- 子任务共享大量隐性上下文，接口无法定义；
- 没有独立验收标准；
- 预算/延迟紧；
- 汇总器会掩盖专家之间的重要分歧。

### 课堂实验

同一份教案任务运行两种实现：

1. 单智能体：一次完成并自检；
2. 多智能体：课程专家、教学法专家、可访问性专家、安全专家并行，汇总器保留分歧。

比较：来源正确率、事实错误、不可执行建议、遗漏风险、教师修改量、总 tokens、延迟、失败率和教师偏好。只有当多智能体在预注册指标上产生足够增益，才保留复杂架构。[S05][S08]

## 十二、Evals 与 observability：两者不能互换

### 1. 七层评测栈

| 层 | 问题 | 示例指标 |
|---|---|---|
| 工程 | 流程是否按约定运行？ | 工具选择、schema、handoff、停止、重试、超时 |
| 来源 | 内容是否忠于批准来源？ | 引用可打开率、claim-support、过期源率、无来源断言率 |
| 教学 | 是否促进学生思考？ | 首答泄漏率、提示阶梯遵守率、追问质量、学生尝试次数 |
| 学习 | 学生是否真正学会？ | 无 AI 新题、延迟测、解释质量、跨情境迁移 |
| 人类工作 | 是否帮助教师而非增加隐形负担？ | 采纳/编辑/拒绝率、节省时间、每条反馈耗时、接管率 |
| 安全与权利 | 是否保护学生？ | PII 泄漏、越权工具、危机漏转、拟人化、申诉与删除成功率 |
| 公平与运营 | 谁受益/受损，代价如何？ | 年级/语言/障碍/基础水平切片、成本、延迟、可用率 |

### 2. 一个合格 eval set 的最小组成

- 20 个正常案例；
- 10 个来源冲突/资料不足案例；
- 10 个学生要求直接答案、代写或绕过规则案例；
- 10 个包含个人数据、错误年级、危机或高风险决策案例；
- 10 个可访问性、方言/多语和文化情境案例；
- 每个案例有预期动作、禁止动作、可接受输出、必须引用的来源和人工评分说明。

生产前至少运行多次，以暴露非确定性；高风险边界失败应 fail closed，不以平均分抵消。

### 3. Trace 的正确用法

- trace 用于回答“发生了什么”：模型生成、工具调用、handoff、guardrail、错误和延迟。[S01]
- eval 用于回答“是否足够好”：是否忠实、有效、安全、公平、可迁移。
- 教育 trace 在写入前去标识化；禁用不必要的敏感输入/输出捕获；设置访问控制与删除期。
- 单元测试可使用固定脚本模型验证编排；真实模型、网络、browser 和 MCP 行为仍需集成/端到端测试。[S01]

## 十三、未成年人、隐私与教师监督

### 最小治理包

1. **儿童权利影响评估**：在设计、每次重大模型/功能更新和新市场发布前完成；覆盖安全、隐私、公平、透明、发展与福祉、包容和救济。[S16]
2. **数据地图**：列明采集、推断、发送、存储、共享和删除的每个字段；默认不采集姓名、联系方式、完整成绩、IEP、健康或辅导记录。
3. **年龄与监督**：按本地法律、学校政策和供应商条款设置独立使用边界；年龄不明时采用更严格模式。[S15]
4. **明确 AI 身份**：用年龄适切语言说明“这是 AI，不是人”；不得把系统描述为朋友、治疗师或可信赖的知心人，也不得暗示排他性、依赖或情感优先地位。[S16]
5. **责任链**：每个学生面向流程有教师/机构 owner、申诉渠道、事故响应人和 kill switch。
6. **供应商审查**：合同目的限制、训练用途、子处理者、数据驻留、保留/删除、泄露通知、模型变化、退出与导出。
7. **公平与可访问性**：按年级、语言、障碍、基础水平等切片评测；让受影响的教师、学生与照护者在安全、有意义的方式下参与评估。

### 法律边界说明

本简报不是法律意见。美国 FERPA 的一般规则是未经书面同意不得披露教育记录中的可识别信息，但存在有条件例外；儿童在线数据还可能涉及 COPPA。其他国家/地区有不同的教育、隐私、儿童权利、AI 和劳动规则。课程必须教学习者：**在任何真实部署前由机构隐私/法务负责人依据所在地、年龄、数据类型、供应商和用途作具体审查**。一手补充链接见 provenance 的 `[J01]`、`[J02]`。

## 十四、Capstone：K-12/大学双路径、教师/学习者/治理三通道教育智能体

### 任务

为一个真实但去标识化的单元，建造：

- **教师通道**：从批准课程源检索，草拟教案、提示阶梯、评测与差异化建议；
- **学习者通道**：只使用教师签发的内容，执行诊断、提示、学生尝试、反馈、反思与无 AI 迁移任务；
- **治理通道**：显示来源、权限、审批、数据保留、模型/规范版本、风险事件和关闭开关。

### 技术约束

- 至少一个只读 MCP 课程连接；
- 浏览器仅允许公共、白名单、只读网站；
- 所有外部写动作关闭或强制人工审批；
- 先交付单智能体版本；多智能体扩展必须提供 A/B 证据；
- trace 不含直接标识符，敏感捕获显式关闭；
- 任何低置信、来源冲突、危机或越权请求都停止并转交。

### 交付物

1. 教育智能体契约；
2. 数据流与权限图；
3. 来源清单和固定版本；
4. 教师/学习者两条工作流；
5. 60+ 案例评测集与评分规则；
6. 单/多智能体比较（若使用多智能体）；
7. 无 AI 迁移与延迟测计划；
8. 儿童权利/隐私影响评估；
9. 事故、申诉、删除和 kill-switch 演练；
10. 一页“发布/不发布”证据决策。

### 评分建议（100 分）

| 维度 | 分值 | 不可妥协条件 |
|---|---:|---|
| 教学设计与迁移 | 20 | 有明确学习结果、提示阶梯、无 AI 新任务 |
| 来源与事实忠实 | 15 | 关键主张可回链；无伪造引用 |
| 架构与权限 | 15 | 最小权限；MCP/工具/编排边界清楚 |
| 人类监督 | 15 | 高风险动作和决定有明确 owner/审批/申诉 |
| Evals 与可观察性 | 15 | trace 与 eval 分开；有重复运行、失败分析和人工抽检 |
| 儿童权利、隐私、公平 | 15 | 无直接 PII 演示；有影响评估、删除期和群体切片 |
| 可用性与交付 | 5 | 教师能在有限时间内理解、接管和停止 |

出现以下任一项即不能发布：伪造来源、学生 PII 泄漏、未经审批写外部系统、自动高风险决定、危机不升级、第一步给原题完整答案、无法停止/删除、把 X/星标当效果证据。

## 十五、建议教学节奏

建议 6 周、每周 2 个模块：

- 每模块 60–90 分钟异步内容；
- 每周 90 分钟 studio；
- 第 1–2 周完成低风险、只读实验；
- 第 3–4 周完成 K-12/大学二选一工作流；
- 第 5 周完成评测、隐私与红队；
- 第 6 周完成小型 shadow/teacher-only 试点和 capstone 审查。

若压缩为工作坊，可用三条路径：

- **180 分钟教师版**：M1/M2 → M5 或 M6 → M10/M11 → 发布决定；
- **1 天开发者版**：M1–M4 → M9/M10 → M11/M12；
- **6 周证书版**：完整 12 模块 + capstone。

## 十六、研究空白与必须保守表述之处

1. 尚缺“自主教育智能体”跨学科、跨地区、跨年龄、长期的高质量效果证据。
2. 对低龄儿童、特殊教育、多语/低资源环境、残障学习者的证据仍不足。
3. 很多研究测短期正确率、满意度或使用量，较少测延迟保持、跨任务迁移、教师长期负担和制度性公平。
4. 模型、prompt、供应商安全层和产品 UI 持续变化；2025/2026 的效果不能自动映射到未来模型。
5. 多智能体教育项目展示了丰富架构，但多智能体相对单智能体的教学增益仍需直接实验。
6. 轨迹、日志和“可观察性”可能反过来扩大儿童数据风险；隐私保护本身也需要验证。
7. 机构层面的采购、教师培训、家校沟通、申诉和事故响应往往比 demo 更决定成败。

课程对外不应使用以下无边界表述：

- “AI 导师已被证明普遍优于教师/课堂”；
- “多智能体一定比单智能体好”；
- “使用 MCP 就安全、准确、合规”；
- “开源/高 stars 证明有效”；
- “学生完成得更快就是学得更好”；
- “人类在环”本身即可保证责任落实。
