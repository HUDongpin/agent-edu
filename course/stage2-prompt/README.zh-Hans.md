## 要注意什么

**`"could I grab a large flat white when you get a sec"` 现在能用了**，而你从没为它写过规则。这就是任何人把模型放进程序里的全部理由。接着脚本会跑三组探测，每一组都会从你手里拿走一点东西。

**探测 1 —— 它稳不稳？** 同一个含糊的问题，问五次，数有几种不同的回答。它可能只有一种。参考提示词在课程默认设置上的一次真实运行（`deepseek-flash`，effort 为 low，没有设置 temperature，思考关闭）记在 [stage2.json](../cafe/recordings/stage2.json) 里：20 个会话，其中十一个只有 1 种回答，九个有 2 种。100 次里有 91 次是空订单，而且 `needs_confirmation` 为 true。另外九次点出了一杯饮料。没有一个会话给出五种不同的回答。你自己的提示词可以落在别的地方。这份记录是这个模型、这条提示词当时的结果，不是对下一次的承诺。

**探测 2 —— 它对不对？** 另一个问题，也是真正要紧的那个。它会拿报出的价格去对真实菜单。你从没把菜单给它，所以它印出来的数字不是查来的。在那份记录里，清楚的订单五次都一样：flat white，大杯，4.50，`needs_confirmation` 为 false。菜单上这杯是 5.10。稳定，而且是错的。含糊问题返回的空订单也不是一份核对过的订单。**一致不是正确。** 会晃的模型明显是在猜；会重复自己的模型也在猜，只是藏得更好。

**探测 3 —— 措辞会不会带动它？** 五种方式点同一杯饮料。真顾客从不会一字不差地重复自己。盯着 `needs_confirmation` —— 那个决定你收钱之前要不要再问一句的旗标 —— 也盯着商品本身。在那份记录里，三种会话、每一种说法，这个旗标都是 true。商品没有站住：有的说法回来是空的，有的点出一杯，名称和价格也不是同一个值。措辞带动了订单。它没有翻转旗标。

清楚的订单是稳的那一个，价格却仍是编的。含糊的问题大多是同一张空订单，九个会话里出现了第二种回答。**模型不是一颗你可以指望的骰子，也不是一次查询。它会去填你留下的缺口，或者不去填，两者都不是正确。** 第 4 阶段是故意把那个缺口补上。五次调用分不出是哪一种。第 3 阶段负责去数。

如果你的数字和朋友的不一样，或者和这份记录不一样，那也是重点。试一下 `CAFE_PROVIDER=anthropic` 或 `CAFE_MODEL=deepseek-v4-pro`。一个模型有多稳，是那个模型和那条提示词的性质，不是任务的性质。

## 关于 JSON

`ask(prompt, { schema })` 要的是 **结构化输出**：回复被约束在你的 JSON Schema 里，所以它 *不可能* 以错误的形状回来。你可能见过更老的代码在提示词里求 —— *"reply with ONLY valid JSON, no preamble"* —— 然后用正则抠出来，解析失败就重试。功能存在的地方，整套装置都被传入 schema 取代了。

功能不存在的地方，你就得自己写这套装置。**DeepSeek 接受 `output_config.format` 然后默默忽略它** —— 你期望 JSON，拿到的却是胸有成竹的散文，这比报错更糟，因为报错至少会告诉你。所以 `cafe/llm.ts` 会识别服务商，把 schema 用文字写进提示词，再自己校验回复。打开它，阅读 `schemaFallback` 和 `extractJSON`；那就是你否则要从头写的退路，而知道什么时候仍然需要它，才是真正的技能。

## 关于价格

仔细看它对那杯 flat white 收了多少。你从没把菜单告诉它。把这个念头留到第 4 阶段 —— 你先需要一种 *测量* 它错到什么程度的办法，那就是第 3 阶段。

## 逐条讲解 TODO

`run.ts` 里只有一个 `TODO`。

**写出 `SYSTEM`。** 在 `run.ts` 里把提示词写进 `SYSTEM`。模型要把顾客的一句话变成符合 `ORDER_SCHEMA` 的订单（字段定义在 `cafe/evalset.ts`：`items`、`total`、`needs_confirmation`）。提示词要讲清任务：点什么、杯型、价格、合计，以及顾客说得不够清楚时把 `needs_confirmation` 设为 true。检查器只要求 `SYSTEM` 非空，并且一句清楚的点单能解析出这些字段。

故意 **先不要** 把菜单贴进去。第 4 阶段才会贴，对比本身就是这一课。没有菜单，模型仍然可以给出正确的 *形状*，同时编造事实。那不是失败，那是基线。
