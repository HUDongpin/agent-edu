## 三、已纠正的课程一致性与安全逻辑

### 3.1 英文与简体中文一致性

- 两种语言的 12 道终测现在使用相同题目 ID、顺序、语义选项 ID、正确语义答案、关键题标记和来源映射；本地化标签则分别由已审校指纹绑定。
- 两种语言的结课项目现在都要求 10 份模块产出物，不再出现英文简版与中文完整版要求不一致。
- 高等教育路径从模块 1 开始；删除了不存在的 “design track” 前置条件。
- 多智能体情境统一为 4 个专职角色：来源核验、教学法/方法、可访问性和安全；协调者不计为第五个专职角色。
- 中文难度改为“入门到高级”，与实际从边界基础推进到部署与评估的路径相符。
- 结课项目明确采用 K-12 / 大学双路径，并同时覆盖教师、学习者和治理三条通道。

### 3.2 评分与高影响决定

交互中的 `grade` 任务现在始终进入停止路径，即便所选权限只是 “draft”。系统不得先作学术判断、先给草拟分数，再要求教师背书。允许的顺序是：教师先作判断，然后智能体只依据该判断准备可编辑的证据摘要或反馈草稿。真实学生数据还必须是机构批准、去标识的输入；默认试点使用合成数据。

### 3.3 产出物与评分规准

多个原先过于宽松的结课标签已补强：

- 任务契约必须写明禁止动作和停止条件；
- 教师 copilot 必须包含学习者活动与可访问性检查；
- K-12 方案必须包含事件响应与退出/停止机制；
- 评测卡必须给出发布门槛；
- 试点计划必须标明具名责任人与审批点。

这些字段是结构门槛，不代表自动质量认证；课程界面继续要求教师进行内容、教学、可访问性和安全复核。

## 四、进度真实性纠错

旧实现把完成状态压缩成布尔值，存在三个严重问题：`10/12` 的终测可在重载后显示为 `12/12`；旧键值可直接伪造模块或结课完成；修改模块产出物后，模块与结课认证仍可能保持完成。第一版 v2 回执随后又被独立审计发现无效短文本、未提供答案、跨标签页旧责任声明复用等弱点。本轮连续对抗审计还发现三层契约缺口：产出物指纹漏掉界面可见的 `evidenceRequirements`；终测 blueprint 曾是手写常量，未绑定题序、语义答案、关键题、来源与阈值；最后，本地化选项文字仍可能在保留 `correctIndex` 的情况下换位。上述问题均已在最终候选中 fail closed 修正。

现已迁移到 fail-closed 的 v2 证据回执：

1. 终测保存精确的 `score`、`questionCount`、`requiredCorrect`、关键题通过状态和课程版本；`10/12` 重载后仍为 `10/12`。真实浏览器流程现在会逐题作答并校验实际保存的分数。
2. 期末测验由 canonical contract 定义题目 ID/顺序、四个稳定语义选项 ID、正确语义选项、关键题、来源映射、题数与阈值；每种已审校语言的四个可见标签及其顺序另由 exact fingerprint 绑定。运行期 copy 是 `{id, label}`，UI 状态、逐题反馈和计分只比较 `selectedOptionId === correctOptionId`，不再使用位置索引。交换中英文标签、交换 ID，或改变任一标签指纹都会被 validator 拒绝并改变 quiz blueprint，使旧回执失效。
3. 英文/简体中文产出物量规与 checkpoint 四个语义选项、正确语义答案及已审校标签指纹已经抽成 locale-specific canonical registry；UI、回执创建器和回读 selector 只使用语义 ID。同样的标签换位或 ID 换位负测会 fail closed，错误 ID 无法铸造 checkpoint 回执，标签契约更新会改变 checkpoint blueprint 并拒绝旧回执。产出物 fingerprint 另绑定显式 rubric schema、最少字数、全部必填标签和全部界面可见的 `evidenceRequirements`；任一要求漂移都会使旧模块与旧 Capstone 失效。
4. 模块完成回执绑定产出物 `revisionId`、内容语言、完整量规 fingerprint、课程版本和 locale-specific checkpoint blueprint；每次读取都会重新运行当前量规，而不是相信 `completed: true`。
5. 结课回执必须同时看到当前 10 个严格模块回执与当前终测回执，并快照全部产出物修订 ID。
6. 修改任一产出物会使对应模块和结课回执失效：完整状态从 100% 降为 **83%**（10/12）；重新记录模块后为 92%（11/12）；基于新 prerequisite fingerprint 重新确认结课后才回到 100%。旧证据快照的责任声明不能复用。
7. 仅浏览另一语言不会改变证据；在另一语言真正保存新版本才创建新修订并触发失效。
8. 旧布尔值一律不计完成。旧文本草稿仍可见，便于使用者重新保存，而不会冒充已验证证据。

进度只是浏览器本地的自我记录，不是成绩、证书、身份凭证或服务器端审计系统。

## 七、残余不确定性

- GitHub `main`、产品文档、X 可见性和项目阶段会继续变化；课程中的技术主张已尽量绑定固定提交，但发布日仍需复查滚动状态。

- 单项研究都不足以证明“智能体普遍提高 K-12 或大学学习”；课程把部署结论保留为需要本地基线、对照、失败样本和无 AI 迁移任务检验的假设。

- 自动结构检查只能确认必要字段存在，不能证明教学质量、事实正确性、公平性或安全性。
- 本轮验证的是隔离工作树中的本地课程包；没有提交、推送或部署到生产域名，因此没有声称 `aicourse.top` 已上线或生产可用。
