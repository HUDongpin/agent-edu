## Evidence model

The nine figures use two acquisition chains:

1. `fig-1`, `fig-2`, and `fig-4` to `fig-9` were captured or rendered by the Course 11 production team. Their X links are practitioner context already cited by the curriculum. The linked posts are not the source of the image pixels, and no creator-post image pixels were copied.
2. `fig-3` comes from the official `openai/codex` repository at an immutable commit and retains its Apache-2.0 licence and notice.

Classification is a factual boundary:

- `codex-app`: current first-party Codex desktop UI captured from a disposable synthetic workspace.
- `codex-cli`: either a historical official CLI illustration or a first-party rendering of an actual CLI transcript.
- `product-output`: a first-party synthetic teaching artefact, not a Codex interface or evidence of sales.
- `repository-handoff`: a first-party synthetic review or delivery record, not a GitHub screenshot or external repository record.

There are four authentic Codex UI or transcript figures: two live app crops, one official historical CLI illustration, and one actual CLI transcript rendering. There are five synthetic downstream teaching fixtures. All eight first-party records use rights basis `first-party-original` and capture method `first-party-synthetic-capture`. The synthetic qualifier refers to the safe workspace and invented data, not to the authenticity of the Codex app pixels or the CLI transcript.

Superseded creator-post image files were removed from the public figure directory through a recoverable Trash move after the replacement manifest was installed. Their X and GitHub claims remain in the course only as attributed contextual sources with explicit evidence limits.

## Reproduction procedure

The actual CLI preflight used the bundled executable in an ephemeral, read-only run:

```sh
/Applications/ChatGPT.app/Contents/Resources/codex \
  -a never \
  -s read-only \
  -C /tmp/course11-codex-demo \
  exec \
  --ephemeral \
  --skip-git-repo-check \
  --ignore-rules \
  --color never \
  "Inspect README.md and acceptance.md only. Return exactly four Markdown sections named Scope, Risks, Verification, and Decision. Do not edit files. Treat all acceptance checkboxes as evidence requirements."
```

The local HTML fixture is retained at `outputs/make-money-with-codex/first-party-captures/figure-fixture.html`. It was served only on `127.0.0.1`, opened in bundled Chromium, set to a 1600 x 900 viewport, snapshotted after each navigation, and captured once for query values 4 through 9. The master PNGs were visually inspected at full resolution. Matching WebP files were produced locally with metadata excluded.

## Verification procedure

Run from the repository root:

```sh
node scripts/check-make-money-with-codex-course.mjs
node scripts/check-make-money-with-codex-course.mjs --release
shasum -a 256 public/courses/make-money-with-codex/figures/*
```

The validator reads `lib/make-money-with-codex/figures.ts`, checks each master and WebP file, parses dimensions, recomputes digests, enforces classification counts, verifies lesson references, reads the first-party rights record, and rejects unverified creator-image rights in release mode. A passing result establishes internal repository consistency, not the truth of remote business claims, future UI currency, trademark permission, legal suitability, or a promise of income.
